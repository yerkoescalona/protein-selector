# Audit and refined plan — protein-selector

**Date:** 2026-08-28
**Auditor:** independent pass (Claude Fable 5), run against the working tree and the real
store, not against the design docs' own account of themselves.
**Scope:** everything — architecture, code, the accumulated data, the measurement itself,
the docs, and `PLAN.md` §25/§26/§27's own open plan.
**Relationship to prior audits:** `docs/code-audit-2026-08-08.md` audited *code quality*.
`PLAN.md` §26 audited *adoption readiness*. This pass audits **measurement validity** —
whether the numbers the tool produces mean what the tool says they mean — which neither
previous pass examined, and which turns out to govern most of the open plan.

---

## Verdict

The engineering is genuinely good and the prior audits were right about that. The gate is
green (`389 passed, 2 skipped`, `ruff`/`ty` clean, verified this pass), the layering claims
hold, the append/upsert-only invariant is real, and the store holds 5,505 real validation
outcomes across 2,473 candidates — an asset most tools in this space cannot show.

**But the tool's central output is not currently trustworthy, and the open plan does not
know it.** The docking lane — 67% of all compute and, by §27a's own analysis, "the only
gate that separates good from bad" — emits a pass/fail label that has never been validated
against a control, and carries at least three uncontrolled confounds present in **100%** of
the stored data. §27d Phase 2 (W3.1/W3.2) then calibrated the *predictors* against that
label, found no discrimination, and retired two of three predictors as a negative result.

That work was methodologically careful and honestly reported. It was also **aimed one level
too high**: when a predictor fails to predict a label, the label is a suspect, and the label
was never put on trial. Retiring the predictors on the strength of an unvalidated label is
the single most consequential thing to revisit, because it has already removed two of the
three components of the "two-part difficulty" that `PLAN.md` §5 calls "the novel piece" and
§2 calls "the highest-value signal".

The refined plan below therefore inserts one new gate — **validate the measurement** —
ahead of everything else in §27d Phase 3 onward, and shows why three of Phase 3's five
tasks are currently un-executable as written.

## Findings

Ordered by consequence. Each states the evidence, so each can be re-checked or refuted.

### F-A (critical) — The docking pass/fail label has never been validated, and carries three uncontrolled confounds

`docking` is 67% of all compute (5.96 CPU-h of 8.96) and produces a 66.3% failure rate,
of which 266 of 270 failures are `docking_quality` — i.e. self-dock RMSD above threshold.
A self-dock is the *easiest* docking test there is. Measured on the real store:

```
self-dock RMSD (n=403):  median 3.76 Å   p25 1.98   p75 5.89   max 15.13
                         ≤2.0 Å: 25.8%    ≤2.5 Å: 34.0%    ≤5.0 Å: 66.7%
```

Published redocking benchmarks for Vina on prepared complexes typically land far above
25.8% under 2 Å. Three specific, separable, and currently unmeasured causes are present:

**A1 — Every receptor in the store is under-minimized, by the tool's own criterion.**
`workflow/config.yaml` sets `md_max_minimization_iterations: 50` and warns in its own
comment to "treat those rows' status with suspicion" and use 200/200 "if you need to fully
trust the MD status for candidate selection." Measured:

```
md_simulation rows carrying the "may not have fully converged" warning:  2281 / 2357  (96.8%)
docking-tested candidates whose receptor came from such a run:            407 /  407  (100%)
```

Per §18, docking uses the MD-relaxed structure as the receptor. So **every stored docking
result used a receptor the pipeline itself flagged as not-converged.** This is not a
hypothetical: it is the entire dataset.

**A2 — The RMSD is not symmetry-corrected.** `vina_docking.rmsd_by_atom_name` matches atoms
by PDB atom name. Atom-name matching correctly fixed bug 9's index-order defect (verified:
`1DB5`/`6IN` matches 28/28 atoms), but it does not handle molecular symmetry — a flipped
phenyl, a carboxylate, a nitro or sulfonate group is chemically identical and geometrically
correct yet scores a large RMSD. This inflates RMSD in one direction only, systematically
producing **false** `DOCKING_QUALITY` failures. `workflow/config.yaml`'s comment on
`dock_rmsd_threshold` still describes the RMSD as "index-order, not symmetry-matched" —
half stale (it is name-matched now), half still true and unaddressed (it is still not
symmetry-matched).

**A3 — There is no minimum-matched-atom guard.** `rmsd_by_atom_name` returns `None` only
when *zero* atom names are shared; with one shared name it returns a one-atom "RMSD" that
`docking_validation.py` then pass/fails a candidate on. Measured over the 237 rows whose
notes record the count: **min 1 matched atom; 11.0% ≤5 atoms; 24.1% ≤8 atoms.**
Inspection of the persisted comparison files shows these are genuinely tiny ligands
(`2LH2`: a single O; `1SXX`: N+O; `1CLL`: C1+C2), not a name-matching failure. Redocking a
one- or two-atom ligand into a padded box is not a meaningful docking test, and its RMSD is
dominated by box geometry.

Ligand size against outcome, joined from the persisted native-ligand blocks (n=370):

| ligand heavy atoms | n | pass rate |
|---|---|---|
| 1–2 | 20 | 15.0% |
| 3–5 | 13 | 46.2% |
| 6–9 | 52 | 30.8% |
| 10–14 | 54 | 29.6% |
| 15–19 | 40 | 20.0% |
| 20–29 | 88 | 40.9% |
| 30+ | 103 | 44.7% |

Two readings, both actionable: tiny ligands (≤5 heavy atoms, 8.9% of the tested pool) are
pedagogically useless and should be gated out cheaply rather than consuming the most
expensive lane; **and** even drug-sized ligands only reach 44.7%, which is what points back
at A1/A2 as the dominant effect rather than ligand triviality.

**A4 — The alignment error is computed and thrown away.** `stages/docking_common.py:123`
logs the crystal→MD-relaxed superposition RMSD at `logger.debug` and never persists it. It
is a third error term folded into every self-dock RMSD, and it is currently not recoverable
from the store at all.

**Consequence.** The self-dock RMSD is the sum of Vina's docking error (wanted), the
receptor's relaxation drift, the cealign superposition error, and a symmetry artifact. No
experiment in this repo separated them. Until one did, "66.3% of candidates fail docking"
was not a statement about the candidates.

> **UPDATE (2026-08-28, same day): the experiment was run — see `PLAN.md` §28c B.4 — and
> it refuted the leading hypothesis above.** Swapping the MD-relaxed receptor for a crystal
> receptor made results **worse** (26.9% → 19.2% pass, paired, n=26), so **A1 and A4 are
> not the dominant confound.** A2 (symmetry) and A3 (coverage) are real but secondary:
> together with a third cause the experiment surfaced — **the pool contains crystallization
> additives, buffers and glycosylation residues that were never docking targets** (49 of
> 370, 13%, passing at 10.2%) — they account for ~8.5 percentage points, moving the real
> pass rate 35.4% → 43.9%. The remaining ~56% failure rate is genuine and still
> unexplained; the leading untested hypothesis is now **ligand preparation** (obabel from
> crystal coordinates, no hydrogens, obabel's own bond perception). The finding below
> stands as *"the label was never validated"*; the specific attribution to the receptor
> was wrong, and is recorded here rather than quietly corrected.

### F-B (critical) — W3.2 retired two predictors against that unvalidated label, and broke Phase 3's own dependency

W3.1/W3.2 were executed carefully: real AUCs, bootstrap CIs, alternatives tested live
before retiring anything. The problem is upstream of the statistics. If the docking label
is substantially driven by receptor under-relaxation, alignment error and symmetry
artifacts (F-A), then **no pre-validation property of the candidate could predict it**, and
AUC ≈ 0.5 is the expected result whether or not a good predictor exists. The negative
result is consistent with "the predictor is useless" *and* with "the label is noise", and
the study cannot distinguish them.

Two downstream consequences the plan has not registered:

1. **The product thesis is now hollow for 2 of 3 exercises.** `predict_modeling_difficulty`
   and `predict_docking_difficulty` are no-arg functions returning `None`
   (`core/difficulty.py:81,140`). So `predicted_vs_measured_gap` — §2's "highest-value
   signal", §5's "the novel piece" — is computable for `md_simulation` only. Measured in the
   shipped deliverable: `modeling_predicted_difficulty`, `modeling_gap`,
   `docking_predicted_difficulty`, `docking_gap` are **0/300 populated**.
2. **§27d Phase 3 is blocked, not enabled.** Phase 3 is annotated "needs W3.2", and **S2.4**
   reads: *"Run the expensive lanes in predicted-tractability order (needs a calibrated
   proxy from W3.2)."* W3.2 delivered the finding that **no calibrated proxy exists** for
   docking — the exact lane S2.4 targets. As written, S2.4 cannot be started. **S2.2**
   (make fpocket opt-in) and **S2.1** are still fine; **S2.5** is fine and is now the *only*
   Phase 3 task with real supporting evidence (S1.4's `pearson(log effort, heavy_atoms)=0.62`
   predicts *cost*, which is a valid ordering signal even though *outcome* is unpredictable).

### F-C (high) — Three pipeline stages produce no decision

The layered funnel is the repo's core design claim (§3). Measured against the code:

| Stage | Work performed | What consumes its output |
|---|---|---|
| Literature (Europe PMC) | 2,473 network requests, a named §3 stage | **Nothing.** `literature_count` appears in the report as a column; `grep` finds zero references in `core/difficulty.py`. §5a lists "literature richness" as a predicted-difficulty input; it is not one. |
| fpocket pocket detection | 2,029 entries, real subprocess compute | **Nothing.** Confirmed by A7 (gates no dockability) and now also post-W3.2 (the only scorer that read `pocket_druggability_score` was the retired docking predictor). |
| Predicted difficulty (modeling, docking) | — | **Nothing.** Always `None`. |

§27a already reports fpocket "gates nothing"; what is new here is that after W3.2 it feeds
nothing either, and that literature has *always* fed nothing. This is not an argument to
delete them — literature richness is a reasonable pedagogical signal and pocket geometry is
worth keeping as a report column — but a five-stage funnel where the middle three stages
are inert should say so, and should not spend network and compute on them by default.

### F-D (high) — The deliverable is not ranked

Nine places promise a ranked output — `PLAN.md:40` (§1, "a **ranked table**"), `PLAN.md:157`
(§8, "One ranked CSV"), `PLAN.md:214` (§12), `README.md:13`, `README.md:55`,
`.claude/CLAUDE.md:21`, `:63`, `:722`, and `core/report.py:3`. There is no ranking anywhere:
`build_report_table` sorts by `pdb_id`, and `demo/report_demo.csv` comes out
`101M, 103L, 105M, …` — alphabetical. `suitable_for` is a filter and `tier` is a label;
neither orders the table.

This is the tool's headline deliverable, and it is the one claim in the docs that is plainly
false rather than merely stale. It is also now harder to fix than it was, because the
natural ranking key was the difficulty score that W3.2 retired (F-B).

### F-E (high) — The credibility artifacts contain no evidence

W1 (demo slice) and W3 (calibration study) are §26.4's "never cut" credibility gate. Both
ship, and both are currently empty of the thing they exist to show.

**`docs/calibration_study.md` reports `n/a` for all three exercises.** modeling:
`n_scored: 0`. docking: `n_scored: 0`. Both because W3.2 made their predictors return
`None` — so the report that was built to publish the calibration evidence now, by
construction, publishes none of it. And `md_simulation`, the one predictor kept, reports
`AUC n/a` too, because:

**The demo slice has zero `md_simulation` failures.** `scripts/build_demo_slice.py`'s
docstring claims the slice is "padded to 300 with candidates chosen to cover every distinct
`(exercise, failure_mode)` combination this store has ever recorded." It is not: the core
(every `complex_md_simulation` candidate) is 296 of the 300 budget, leaving 4 padding slots
for **9** distinct combinations, allocated `ORDER BY exercise, failure_mode` — so the four
alphabetically-first combinations win and all three `md_simulation` failure modes
(`completeness` 4, `parameterization` 28, `stability` 44 in the real store) are absent.
Worse, they are *structurally* absent: complex-MD candidates are by construction MD
successes, so the core can never contain one.

Net effect on a first-time reader, which is exactly W1's audience: the committed demo shows
a **100% MD pass rate** and the committed calibration study shows **no numbers at all**.
The real numbers exist only as prose caveats copied from `PLAN.md`.

## Refined plan

Replaces §27d Phases 3–5 in priority order; leaves Phases 0–2 as the completed record they
are. Same conventions as §27d: every task has a `Done when:` that passes or fails.

### Gate A — Land the tree (blocker, ~0.5 d)

Nothing below is reviewable until this is done, and the work at risk is already finished.

- [ ] **A.1** Commit the in-flight work as logical commits: (i) provenance layer
      (`core/runs.py`, `core/db.py` migrations, `validation_store.py`, tests); (ii)
      calibration (`core/calibration.py`, `scripts/calibration_study.py`,
      `docs/calibration_study.md`, the `difficulty.py` retirements); (iii) demo slice +
      report script + README/INSTALL split; (iv) citability (`LICENSE`, `CITATION.cff`, CI);
      (v) the `models.py` network-at-import fix; (vi) infra (WAL, index, thread pool,
      fpocket scratch cleanup). *Done when:* `git status` is clean except for deliberately
      ignored artifacts, and each commit's gate was green at that commit.
- [ ] **A.2** `2r43.cif` → `cache/` or deleted; the three dated `scripts/*.md` outputs →
      `results/` or `docs/`. *Done when:* `scripts/` contains only source.

### Gate B — Validate the measurement (NEW, the top priority, ~4–6 d)

This gate exists because F-A/F-B mean the tool's most expensive output is currently
uninterpretable. Everything in Gate C and §27d Phase 3 depends on it. Do not re-run the
calibration study, and do not re-derive a difficulty score, before B.5 lands.

- [ ] **B.1 Guard the RMSD against degenerate matches.** Require both a minimum absolute
      matched-atom count and a minimum matched *fraction* of the reference ligand's heavy
      atoms; below either, return a distinct, explicit outcome — not a silent pass/fail.
      *Done when:* a one-atom reference ligand can no longer produce a `DOCKING_QUALITY`
      verdict, and the new outcome is a real persisted `ValidationResult`, never a gap.
- [ ] **B.2 Symmetry-corrected RMSD.** Replace name-matched RMSD with a graph-automorphism
      (symmetry-aware) RMSD — RDKit `GetBestRMS` is already available under the `validate`
      extra, so this needs no new conda dependency. Keep the name-matched value alongside it
      for one release so the two can be compared on the same poses. *Done when:* a ligand
      with a symmetric group (benzene, carboxylate, nitro) that is geometrically correct but
      atom-swapped scores ≈0 Å instead of a large value, locked by a regression test; and
      the two RMSDs are reported side by side over the existing 403 poses.
- [ ] **B.3 Persist the confounds.** Write the crystal→MD-relaxed alignment RMSD
      (`stages/docking_common.py:123`, currently `logger.debug`-only), the receptor's
      minimization-converged flag, and the reference ligand's heavy-atom count as real
      `validation` columns via the same additive `ALTER TABLE` pattern as W2.1/W2.2. *Done
      when:* every confound in F-A is queryable with plain SQL, with no prose parsing.
- [ ] **B.4 The control experiment — the decisive one.** On a fixed set of ~60 candidates
      spanning the ligand-size bands above, redock under four conditions: (a) as shipped;
      (b) crystal receptor instead of MD-relaxed; (c) MD-relaxed with a real minimization
      cap (≥1,000 iterations, or converged); (d) symmetry-corrected RMSD. Report the pass
      rate under each. *Done when:* the contribution of each confound to the 66.3% failure
      rate is a published number, and `docs/` states which condition the tool should ship.
      **This is ~1–2 CPU-h, and it is the highest-value compute this project can spend.**
- [ ] **B.5 Fix the receptor protocol** according to B.4's result, and re-run the docking
      lane under one stamped `run_id` (folds W2.4 in — same compute, both goals). *Done
      when:* every `validation` row carries a `run_id`, A9's untrustworthy rows are
      superseded by recomputation rather than a footnote, and §27a's docking rows are
      re-measured.
- [ ] **B.6 Re-open the W3.2 retirements against the corrected label.** Re-run
      `make calibration` on the B.5 store. If a predictor discriminates now, un-retire it and
      say so; if it still does not, the negative result is finally about the predictor.
      *Done when:* `docs/calibration_study.md` states, per exercise, the AUC against a label
      whose confounds are measured — and the retirement decisions are re-affirmed or
      reversed on that basis, with the previous decision recorded either way.

### Gate C — Make the funnel funnel and the table rank (~3–4 d, needs Gate B)

Supersedes §27d Phase 3. **S2.4 is withdrawn as written** (no calibrated outcome-proxy
exists; F-B) and replaced by C.3, which orders by predicted *cost*, which S1.4 measured and
which is a valid ordering signal regardless of outcome predictability.

- [ ] **C.1 Cheap ligand-quality gate before the expensive lane.** Minimum heavy-atom count
      (and reject monatomic/diatomic ligands and common crystallization additives) at the
      ligand-selection stage. *Done when:* the ≤5-heavy-atom class (8.9% of the docking pool,
      27% pass rate, pedagogically useless) never reaches Vina, and each skipped candidate is
      persisted as a real outcome with a stated reason.
- [ ] **C.2 Retire or wire the inert stages (F-C).** Literature: either feed it into ranking
      (C.4) or make it opt-in and stop making 2,473 network requests by default. fpocket:
      §27d **S2.2** unchanged — make it opt-in, keep the columns explicit-empty. *Done when:*
      a default run performs zero fpocket calls and zero Europe PMC calls unless asked, and
      no stage runs whose output nothing reads.
- [ ] **C.3 Order the expensive lanes by predicted cost, not predicted outcome.** Build the
      two-feature runtime predictor S1.4 supports (`heavy_atoms`, `rotatable_bonds`;
      `pearson(log effort) ≈ 0.62/0.60`) and run cheapest-first, with §27d **S2.5**'s budget
      knob on top. *Done when:* a run capped at 25% of the pool returns measurably more
      completed validations than an unordered 25% on the same pool. (Note this is a weaker
      and *honest* claim than S2.4's — more results per CPU-hour, not better results.)
- [ ] **C.4 Actually rank the table, or stop saying it is ranked (F-D).** Define one explicit,
      documented ordering — measured difficulty and `suitable_for` breadth are available today
      and need no retired predictor — and apply it in `write_report_csv`. *Done when:*
      `demo/report_demo.csv` is not in alphabetical `pdb_id` order, the ordering key is named
      in `README.md`, **or** all nine "ranked" claims are corrected. Do not
      leave both.
- [ ] **C.5 Emit the funnel table** (§27d **S2.3**, unchanged). *Done when:* `make funnel`
      reproduces §27a's gate-selectivity table from the store.
- [ ] **C.6 Populate `ligand_smiles` (F-G).** Persist SMILES at the point they are already
      fetched. *Done when:* the column is populated for every candidate with a resolved CCD
      code, and S1.4-style analyses need no separate live fetch.

## Assumptions and limits of this audit

- **The A1–A3 evaluator assumptions in §27b are untested and I did not test them.** They
  still gate Phase 5 and should still be settled by asking, not inferring.
- **F-A named four confounds and showed all four were present and unmeasured. It did not
  prove which dominates — and B.4, run the same day, showed the leading candidate (the
  receptor) was the wrong one.** That is the intended outcome of a control experiment, and
  the correction is recorded in F-A and in `PLAN.md` §28c B.4 rather than silently edited
  away. What survives unchanged: the label was never validated before decisions were built
  on it, and ~8.5 points of the failure rate were artifacts.
- **The redocking-benchmark comparison is from background knowledge, not a source opened
  during this pass.** Per §11 it is ⚠ candidate: verify against a real benchmark paper
  before quoting a specific published percentage anywhere outside this document. The
  internal measurements (RMSD distribution, convergence rate, ligand-size table, matched-atom
  counts, column population, ranking order) are all reproducible from this repo's own store
  and were run this pass.
- **Superseded:** this pass initially had no validation environment, so the findings above
  were derived from the stored results and the code. The environment
  (`/home/yerko/miniconda3/envs/protein-selector-validation`) was then found to be complete
  — openmm, pdbfixer, rdkit, vina, plip, openff-toolkit, pymol, and the fpocket/obabel
  binaries all import and run — and **B.4 was executed live** (28 real Vina redocks plus a

- One bug in the experiment harness itself, worth recording because it is this repo's own
  lesson again: the first B.4 run failed all 28 candidates at ligand prep with obabel's
  `not a valid PDB file`. Cause was a **trailing newline** in the extracted HETATM block,
  which `prepare_ligand_pdbqt`'s `block + "\nEND\n"` turned into a blank line that
  obabel's PDB reader rejects outright. The repo's own extraction path joins without a
  trailing newline and is unaffected — but it is a one-character difference between a
  working pipeline and 28 silent failures.
